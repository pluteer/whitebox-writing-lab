# 官方 Prompt 设计规范

官方 Prompt 参考了公开源码中的工作流语义，但没有复制第三方代码或文本。核心取舍是：Prompt 负责定义角色、边界和输出契约，程序负责上下文选择、状态校验、版本冻结和落盘。

## 共同结构

每个官方 AI 节点按以下顺序组织指令：

1. **角色**：明确是规划师、写手、审查员、裁决者还是状态档案员。
2. **任务**：只描述当前节点要完成的一个动作，不把整条链塞进一条 Prompt。
3. **输入边界**：说明哪些输入是事实、哪些是建议，以及不能从输入外推什么。
4. **质量规则**：用可检查的行为规则代替“写得好一点”。
5. **输出契约**：固定区块、JSON 字段、枚举值和引用要求。
6. **失败策略**：信息不足时标记待确认，不擅自补全；审查无证据时不报问题。

## 书级规划

新书阶段采用“任务 -> 生成 -> 校验整理”的三节点链。生成节点可以提出方向，但必须把不确定内容列为待作者确认；整理节点不能静默替作者做关键决定。

书级规划至少要覆盖：

- 读者承诺和题材卖点
- 主角欲望、恐惧、能力边界和行为底线
- 世界规则、限制、代价和例外
- 主线冲突、阶段目标、转折因果和结局承诺
- 卷目标、章节跨度和每章状态变化

## 章节写作

写手节点只接收章节任务和上游产物，遵守以下顺序：

```text
章节目标 -> 当前阻力 -> 人物选择 -> 付出代价 -> 状态变化 -> 章尾承诺
```

写手不得：

- 跳过当前章节任务或提前消费后续大纲
- 把世界观设定写成资料卡
- 让角色获得输入中没有的知识
- 用解释替代行动和对话
- 输出分析过程、写作提纲或模型免责声明

## 审查与裁决

审查员和写手必须职责隔离。审查员每条问题必须包含：

```json
{
  "id": "F1",
  "severity": "critical|major|minor",
  "category": "连续性|动机|信息边界|节奏|文风|伏笔",
  "quote": "原文逐字引文",
  "evidence": "为什么这是问题",
  "recommendation": "局部、可执行的建议"
}
```

裁决者只能裁决审查员已经提出的 `finding_id`，不能新增问题。`accept` 和 `modify` 必须提供修订指令，`reject` 必须说明为什么不影响本章目标。

修订者只执行 `accept` 或 `modify`，并输出改动前后证据。未涉及的段落必须保持不变，避免审查闭环变成无边界重写。

## 状态回写

章后状态采用“观察 -> 反射”的两步链：

- Observer 宁多勿少，从正文提取角色、地点、资源、关系、情绪、信息、剧情线、时间和身体状态。
- Reflector 只记录正文明确发生的事实。
- 新伏笔先进入候选列表，不直接伪造稳定 ID。
- 已有伏笔仅被提及时进入 `mention`，只有事实、证据或风险真正变化时才更新推进章节。
- 代码层校验章节号、状态枚举、Hook ID 和不可变快照，模型不能直接写项目资产。

## 变量与上下文

节点使用显式变量，不依赖模型“记住整本书”：

```text
{{input.text}}   上游 Artifact 的文本视图
{{input.json}}   上游 Artifact 的结构化内容
{{project.title}}
{{chapter.number}}
```

长篇上下文应遵循“最小充分集”：当前任务、硬设定、相关角色、相关伏笔、必要的近期摘要。不要把所有历史章节全文重复注入。

## 参考项目的可复用结论

- AI-Novel-Writing-Assistant：先用自动导演收敛书级方向，再交接到世界、角色、卷章、章节执行和质量修复；适合借鉴阶段入口和检查点。
- InkOS：把 Planner、Composer、Writer、Observer、Reflector、Auditor、Reviser 分开；适合借鉴输入治理、增量状态 Delta、事实提取和一次受控修订。
- 笔枢 / PenGen：把内容生成、知识检索、质量检查和自动驾驶状态机拆开；适合借鉴有来源证据的上下文与检查点快照。

## 不做的事

- 不把第三方 Prompt 原文复制进本项目。
- 不用一条超长 Prompt 代替状态模型和校验器。
- 不让模型直接声称“已保存”“已修改设定”，真实完成状态以 Artifact、事件和文件版本为准。
