# 官方默认工作流

Whitebox Writing Lab 的默认作品流程是一条可暂停、可审计、可人工接管的长篇小说生产链。新建项目后会自动创建作品画布和官方 Workflow 绑定，用户只需要配置一个模型并填写当前目标即可开始。

## 使用方式

1. 在“设置”中配置任意一个可用模型。
2. 在作品画布选择一个阶段。默认从“新书立项”开始；已有明确设定时可以直接选择“章节生产”。
3. 在右侧简单工作台填写本阶段任务，点击“运行当前阶段”。
4. 查看每一步的结果和运行证据。需要修改提示词时点击步骤，复杂需求再切换到“编辑”模式。
5. 章节生产完成后，在预检窗口选择执行范围。系统会在“人工审批”通过前阻止章节归档和状态写入。

## 默认阶段

| 顺序 | 阶段 | 默认行为 | 主要产物 |
| --- | --- | --- | --- |
| 01 | 新书立项 | 收敛题材、卖点、读者承诺、叙事策略和边界 | 立项案 |
| 02 | 世界观构建 | 建立会影响剧情的规则、限制、代价和社会结构 | 世界观草案 |
| 03 | 角色设计 | 设计欲望、恐惧、关系、能力边界和可辨识声纹 | 角色档案 |
| 04 | 故事规划 | 将事件组织成因果、选择、升级、失败代价和结局承诺 | 故事规划 |
| 05 | 卷纲与近期大纲 | 将长期方向拆为卷目标和可直接开写的章节任务 | 卷纲、章节表 |
| 06 | 章节生产 | 起草 -> 独立审查 -> 裁决 -> 定向修订 -> Diff -> 质量门 -> 审批 | 草稿、审查集、修订稿、Diff |
| 07 | 章后状态回写 | 从已批准章节提取状态变化，仅生成提案，不直接覆盖设定 | StatePatch 提案 |
| 08 | 拆书分析 | 导入 TXT/Markdown，Split -> Map -> Join -> Report | 拆书报告 |

## 设计原则

- **先书级、后章节级**：先确定读者承诺、世界和角色，再拆卷纲，避免每章独立发挥。
- **先生成、后审查**：审查与裁决是独立节点，模型不能替作者静默改稿。
- **证据优先**：上下文、Prompt、模型、Attempt、Artifact 和血缘都进入运行快照。
- **人工掌舵**：审批前不会写入 `manuscript/`；状态回写先生成结构化提案。
- **可恢复生产**：每个阶段都可单独运行，整条链支持从当前阶段运行到下游，失败节点可重试。
- **官方可分叉**：首次修改官方 Workflow 时应另存为项目流程；官方原版不会被用户修改污染。

## 参考取舍

本流程独立实现，仅参考公开产品描述和工作流思想：

- AI-Novel-Writing-Assistant：从一句灵感进入自动导演、世界/角色/卷章规划、章节执行、审校修复和状态回灌。
- InkOS：shared draft 建书，以及 `write-next`、`draft`、`audit`、`revise`、`rewrite`、`resync` 的章节状态语义。
- 笔枢 / PenGen：将长链路拆成可恢复的阶段和可审计的生产步骤。
